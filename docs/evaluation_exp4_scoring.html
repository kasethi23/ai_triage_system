Scoring severity only on calls that can actually be triaged

Same classifier, same 280-record test set, the same predictions — the only change is how we score. ~30% of the corpus is degraded; some records are truncated to un-triageable fragments (e.g. "call me about bed 10"). Those carry a pre-degradation severity but no content — the model correctly flags them as insufficient-detail, yet the old scoring still graded their severity.

What the fix reveals

  • 4 of the 5 "missed criticals" were truncated fragments the model correctly flagged as un-triageable. Removing them from the severity denominator: 5 misses → 1.
  • Degraded accuracy is 72.6%, not 62% — the un-triageable truncations were dragging the whole slice down.
  • Cost-weighted error drops ~70% (missed-critical 5→1 at ×100 each).
  • The insufficient-detail flag rate stays 100% — scored separately, as its own capability.

Why this is a fix, not cheating

  • Records are excluded by ground-truth un-triageability — not by whether the model got them right, so no failures can be cherry-picked.
  • Both numbers are always reported (all-records and triageable).
  • It matches the product: an insufficient-detail call is routed to a human regardless of the model's best-guess severity, so grading that guess measures nothing real.
Takeaway. The classifier didn't change — the measurement did. Its honest recall on triageable critical calls is 98.1% (the single remaining miss is a genuine electrolyte judgment call). The apparent 91% "ceiling" was the evaluation double-penalizing the model for messages it had correctly identified as un-triageable. This is the error analysis (Exp 3) turning into a measured fix (Exp 4) — exactly what the harness is for.
